# 0.3.17 — 2026-11-26

- **Mac 자동 업데이트가 옛 프로세스를 끝내지 못하던 결함**: 입력기 자신이 실행하는 get.sh의 `pkill -x KoEnJa`는 자기를 띄운 입력기(조상 프로세스)를 건너뛰어(macOS pkill/pgrep의 기본 동작) 옛 프로세스가 지워진 바이너리로 계속 돌았고, 그 프로세스의 업데이터는 릴리스가 여전히 자기보다 새롭다고 보아 **10분마다 같은 업데이트를 다시 설치**했습니다(Contents 교체 → `lsregister -f` → 입력 소스 재등록 → 0.3.16부터는 입력 소스를 ABC로 바꿨다 되돌림 → `killall TextInputMenuAgent`). 0.3.13–0.3.16의 자동 업데이트가 모두 해당. 이 Mac의 시스템 로그에서 밤새 약 90회 확인.
- 수정: 새 복사본의 `KoEnJa --register`가 먼저 같은 번들의 다른 프로세스(옛 입력기, 설정 창)를 SIGTERM → 3초 대기 → SIGKILL로 멈춘 뒤 등록합니다(`Registration.stopOtherCopies`). 업데이트는 옛 복사본의 get.sh를 실행하므로 0.3.15·0.3.16 → 0.3.17 업데이트에도 바로 적용됩니다. get.sh도 `pkill -a` + SIGKILL + 대기로 고쳤고, 업데이터는 설치가 끝났는데도 살아 있으면 스스로 종료합니다(다음 키에서 새 복사본이 뜸).
- 옛 프로세스가 멈춘 뒤 Slack·LINE처럼 그 전부터 입력 중이던 앱은 0.3.16의 입력 소스 되돌리기(`--reselect`)로 다시 연결됩니다(앞에 있는 앱 기준; 뒤에 있던 앱은 그 앱으로 돌아가 입력 소스를 한 번 바꾸면 복구).

**日本語**: 入力メソッド自身が実行する get.sh の `pkill -x KoEnJa` は、自分を起動した入力メソッド（祖先プロセス）を除外するため（macOS の pkill/pgrep の既定動作）、古いプロセスが残り、そのアップデーターが同じアップデートを 10 分ごとに再インストールしていました（0.3.13–0.3.16）。0.3.17 では新しいコピーの `--register` が先に古いプロセスを止めてから登録します。0.3.15/0.3.16 からの自動アップデートにも適用されます。

**English**: The `pkill -x KoEnJa` in get.sh never reached the input method when the input method itself ran get.sh (its updater): macOS pkill/pgrep leave out their own ancestors. The old process lived on, and its updater, still seeing the release as newer, installed it again every ten minutes (0.3.13–0.3.16). In 0.3.17 the new copy's `--register` stops the old process first, then registers; updates from 0.3.15 and 0.3.16 get this too.
